## 1. 固定阅读顺序

所有执行者和验收者只需按顺序读取：

1. `DECISIONS.md`：本轮允许实施的唯一需求边界。
2. `WORKBUDDY-TASKS.md`：任务批次、允许修改范围和验收标准。
3. `CHANGELOG.md`：WorkBuddy 实际修改、测试结果和偏差。
4. `ACCEPTANCE.md`：独立 GPT 的验收结论。

可直接复制给两个工具的启动指令见 `PROMPTS.md`。

如上述文件与历史问题清单冲突，以 `DECISIONS.md` 为准；如需改变决策，停止开发并返回项目主控，不得由执行者或验收者自行改写需求。

## 2. 角色与写入权限

| 角色 | 可写文件 | 职责 |
|---|---|---|
| 项目主控 | 全部四份文件 | 决策、边界调整、最终验收 |
| WorkBuddy | `CHANGELOG.md` | 按任务实施，记录真实改动与测试；不得修改决策和验收结论 |
| 验收 GPT | `ACCEPTANCE.md` | 独立检查代码、测试和界面；不得替 WorkBuddy 修代码或修改需求 |

同一时间只允许一个执行工具修改代码。验收期间冻结代码；如验收不通过，由主控将问题退回 WorkBuddy，修复后再重新验收。
