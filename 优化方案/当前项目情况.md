# ZNAWCA 当前项目情况

## 1. 项目定位

ZNAWCA 是 Windows 本地学习工具。用户提供结构化学习资料、Excel 和媒体文件，系统自动生成学习与测试题，主要面向个人或家庭使用。

ZNAWCA 不等同于 Anvil：前者输入学习资料并自动出题；后者由作者设计课程，面向外部学习者发布或销售。当前按两个产品分别梳理需求，底层能力可考虑复用。

## 2. 需求资料基线

- 原始表达：`客户需求原始表述/ZNAWCA.docx`、`客户需求原始表述/ZNAWCA微信沟通.docx`。
- 中文翻译：`客户原始需求全文翻译.md`。
- 初版开发规格：`Znawca 需求规格说明书 V1.0.docx`。

需求分析以客户原始表达为准；初版规格用于核对既有设计和实现，不自动覆盖后续客户反馈。

## 3. 当前实现

- 技术形态：Electron、React、TypeScript，本地离线运行。
- 已具备：课程导入与校验、学习/测试模式、多种出题方向、筛选、严格/宽松干扰项、计时、成绩与困难内容记录、多语言界面及媒体支持。
- 最近一次检查：类型检查通过；23 个测试文件、97 项测试通过。
- 测试通过仅说明已覆盖行为正常，不代表需求、架构和未覆盖场景均正确。

## 4. 已识别的优化主题

### 课程与知识模型

- 一对多属性可能产生答案不唯一的反向题。
- 需定义每列可作问题、答案、双向或仅筛选的角色。
- 是否支持属性/媒体之间的横向出题仍待确认。
- 需区分难度递进、固定题序、随机策略和 Excel 行顺序。

### 数据与导入

- 上下标、Unicode、空格、分隔符和答案顺序的兼容规则。
- Excel 首行、课程名称、语言后缀和数据起始行的统一规则。
- 多语言课程共享媒体、媒体目录和稳定引用方式。

### 学习交互与反馈

- 四个图片或音频选项采用 2×2 布局，避免滚动。
- 问题和答案的扬声器、关联音频与自动播放规则。
- 进度显示改为总数、已掌握数和剩余数。
- 正确/错误提示音后播放正确答案音频。

以上均为待梳理问题，不等于全部已确认实施。

## 5. 当前未决事项

- 一对多关系何时禁止反向题，何时生成多选题。
- 列角色的标记方式和默认行为。
- 属性/媒体交叉关联是否属于真实需求。
- 语言工作簿、课程名称、文件夹和媒体引用的最终数据结构。
- 难度等级与固定顺序是否属于 ZNAWCA；原始沟通中的相关提议明确指向 Anvil。
- 在线版本是否仍属于 ZNAWCA 的实际计划。

## 6. 当前工作区状态

- 项目目录已重新分区，优化讨论统一位于本目录。
- 工作区目前存在大量未提交的目录移动和代码修改，尚未形成干净开发基线。
- 在完成差异审查、确认改动归属并建立可回退节点前，不应发起新的大范围代码修改。

## 7. 协作与实施原则

- 本对话框负责需求确认、方案定稿和最终验收。
- GPT/Codex 负责需求、数据契约、架构、任务拆分和高风险审查。
- WorkBuddy/Trae 执行范围明确、可自动验证的小任务。
- 每批只处理一个需求主题，必须包含规则、非目标、允许修改范围、测试要求和验收标准。
- 同一批文件不得由多个工具同时修改。

## 8. 下一步

1. 逐条对照原始表达、初版规格和当前实现。
2. 将需求分为：已确认、待客户确认、不实施。
3. 补充客户未考虑但会影响正确性、可用性或数据安全的边界场景。
4. 按优先级形成“场景—问题—规则—验收标准”的改进方案。
5. 建立干净代码基线后，再向 WorkBuddy/Trae 分批下发修复任务。
